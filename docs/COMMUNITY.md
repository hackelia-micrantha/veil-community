# Participating in Veil Community

This is the public interface for product questions, responsible research discussion, documentation improvements, and feedback. The core implementation and engineering roadmap are maintained privately.

## Useful contributions

- **Use cases:** Explain who needs the feature, what they are trying to share or recover, and what would make it genuinely useful.
- **Research:** Supply a publicly accessible paper and identify the question it helps test. Separate reported results from independently reproduced ones.
- **Experience reports:** Describe browser/device/file-format behavior using sanitized, synthetic data; include reproduction steps when possible.
- **Documentation:** Improve clarity, accessibility, terminology, broken links, and the distinction between available and aspirational features.
- **Design questions:** Propose verifiable product contracts and failure behavior without assuming private internal details.

Open an [issue](https://github.com/hackelia-micrantha/veil-community/issues) for a bounded proposal or defect. Before submitting, check for an existing discussion or issue; avoid duplicate tracking. Repository maintainers decide whether an issue belongs here, in private engineering, or outside the current scope.

## Public disclosure boundary

**Do not post** original private images, recoverable personal data, real encryption keys, customer files, credentials, unpublished vulnerabilities, internal architecture, protected source, model weights without redistribution rights, or third-party copyrighted content without permission.

A well-written public report uses a synthetic fixture, a narrow problem statement, and only enough context to reproduce the behavior. If the issue might enable a security exploit or expose sensitive data, **do not open a public issue**: follow the [Veil Community private reporting instructions](../SECURITY.md).

## Expectations

Features described as *research*, *experimental*, or *proposed* have no release or support commitment. Public comments are welcome, but maintainers may decline work that exposes private IP, makes unsupported security claims, duplicates an internal contract, or adds long-term maintenance cost without a demonstrated user benefit.

Read the [organization contribution standard](https://github.com/hackelia-micrantha/.github/blob/main/CONTRIBUTING.md) and [governance](https://github.com/hackelia-micrantha/.github/blob/main/GOVERNANCE.md). This repository intentionally uses the organization's inherited GitHub community-health defaults rather than copying them into local files.

Submit only material you have the rights to contribute on those terms. External papers, logos, and links remain subject to their original ownership.
